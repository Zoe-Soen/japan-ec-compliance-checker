# 日本电商网站在地合规检查工具｜MVP 商业变现逻辑方案

## 1. 结论摘要

建议采用以下商业路径：

> **产品形态使用 Web SaaS；验证期按次或出售额度包；需求稳定后推出“基础订阅／年费＋包含额度＋超额付费”的代理套餐。**

不建议把普通买断式工具包作为主产品，也不建议 MVP 一上线就提供无限次月费订阅。

买断式私有部署可以作为未来面向数据敏感企业的高价方案，但软件交付、规则更新和技术支持必须分开计价和约定期限。

本方案只建立商业逻辑和验证顺序，不决定最终价格，也不代替实际客户访谈、税务确认或合同审查。

## 2. 已确认事实、推算与待确认项

### 2.1 已确认事实

- 第一批目标用户是面向日本市场的中文代理运营人员。
- 目标用户会在一年内反复检查多个客户网站。
- 同一网站在新商品上线时也可能产生范围更小的重复检查需求。
- 产品需要持续更新检查规则、页面提取方式和浏览器兼容性。
- 当前 MVP 只覆盖日本 B2C 独立站、普通实体商品和约 30 条基础规则。
- 产品是风险筛查工具，不提供法律认证。

### 2.2 推算

- 代理运营人员比单个商家更可能形成持续使用，因为检查对象来自多个客户。
- “新商品快速检查”和“整改复查”可能成为网站完整体检之后的主要复购来源。
- 用户的工作量可能按项目集中发生，而不是每个月平均发生，因此单纯月费未必是最容易接受的起步方式。
- 代理可以把检查成本计入客户项目，因此按次额度通常比个人消费者订阅更容易解释。
- 集中更新规则和保留历史结果，是 SaaS 相对本地买断工具的长期价值。

以上均需要通过真实使用和付费实验验证，不能仅凭访谈意愿视为成立。

### 2.3 待确认项

- 第一批用户一年分别检查多少网站、多少新商品，以及复查多少次。
- 用户更习惯按项目采购、充值额度，还是按月／按年采购工具。
- 一次完整检查和一次商品快速检查能够节省多少人工时间。
- 用户愿意支付的价格，以及谁拥有采购决定权。
- 代理是否需要团队账号、白标报告和客户项目管理。
- 云端处理截图和页面证据是否会成为采购障碍。

## 3. 目标付费客户与使用者

### 3.1 优先客户

首轮优先面向小型代理公司、跨境电商代运营团队和独立顾问，而不是直接面向偶尔检查一次网站的单个商家。

理由：

- 代理同时服务多个客户，检查频率更高；
- 能够比较工具与人工检查的时间差；
- 有机会把报告直接用于客户整改沟通；
- 对规则更新、历史记录和统一输出格式更敏感。

### 3.2 购买者与使用者

| 角色 | 关心的问题 | 产品需要证明的价值 |
|---|---|---|
| 代理负责人 | 是否降低项目成本、能否标准化交付 | 减少检查时间和遗漏，报告可以交付客户 |
| 运营人员 | 是否容易使用、结果是否可信 | 不查法规原文也能开始整改 |
| 商家客户 | 为什么要改、应该怎么改 | 证据、依据和具体建议清楚 |
| 网站制作方 | 修改范围是否明确 | 能够定位页面和字段，不需要反复沟通 |

## 4. 客户购买的不是“扫描次数”

收费单位可以是额度，但用户实际购买的价值包括：

- 少花人工时间寻找关键页面和重复核对字段；
- 降低遗漏高风险信息的概率；
- 快速生成可交给客户和制作方的整改清单；
- 修改后能够复查并保留证据；
- 持续使用更新后的日本规则基线。

因此对外不应只宣传“自动扫描 30 个页面”，而应强调“更快发现问题并推动整改”。

## 5. 为什么主产品选择 SaaS

### 5.1 与持续价值匹配

- 检查规则和官方依据会更新；
- 网站框架和页面结构会变化；
- 同一客户会发生整改、改版和新商品上线；
- 代理需要管理多个客户和历史结果。

这些价值都需要集中更新和持续运行，适合在线服务。

### 5.2 与代理工作方式匹配

- 无需为每位运营人员安装和更新桌面软件；
- 检查记录、报告和项目可以统一管理；
- 运营人员可以把报告链接或导出文件交给客户；
- 新规则发布后不需要逐台电脑更新。

### 5.3 买断式工具包的合理位置

买断式不作为普通方案，但可以服务以下客户：

- 明确禁止把页面或截图发送到外部服务；
- 必须使用公司内网、固定 IP 或本地证书；
- 愿意承担本地部署、升级和运行环境；
- 能接受较高的一次性部署费及年度规则更新费。

这种方案本质上是“企业私有部署＋维护合同”，不是低价永久买断。

## 6. 建议的收费结构

### 6.1 验证期：按次或额度包

首批试用不要求用户订阅，按检查额度收费：

| 检查类型 | 建议计量逻辑 | 当前状态 |
|---|---|---|
| 网站完整检查 | 消耗较多额度 | 当前 MVP |
| 新商品快速检查 | 消耗较少额度 | MVP+1 候选 |
| 整改复查 | 首次免费或消耗少量额度 | MVP+1 候选 |

验证期可以人工收款、发放额度和记录用量，不急于开发复杂支付系统。

### 6.2 稳定期：代理套餐

当重复使用得到验证后，再提供：

- 月付或年付的基础账户；
- 套餐内包含一定检查额度；
- 超出部分购买额外额度；
- 更高档套餐增加团队成员、白标报告、历史对比和客户管理。

不建议无限次使用。网站复杂度、页面数、OCR 和扫描时间都会影响成本，无限次会让重度客户的资源消耗与收入失去对应关系。

### 6.3 特殊客户：私有部署

私有部署应拆分为：

1. 初次部署和环境配置费用；
2. 软件使用授权；
3. 年度规则更新和技术支持；
4. 定制规则、接口或白标的单独费用。

停止支付更新维护后，客户可以继续使用已购买版本还是必须停止使用，需要在合同中明确，不能默认永久提供最新规则。

## 7. 三种检查产品

### 7.1 网站完整检查

适用：新网站上线、广告开户前、网站改版或首次接触客户。

输出：网站级风险报告、关键页面证据和优先整改清单。

这是 MVP 唯一需要实现和收费验证的检查产品。

### 7.2 新商品快速检查

适用：现有网站新增普通商品或更换商品页面表达。

未来可能检查：

- 商品名称、价格、税费和送料；
- 交付、退货和取消信息；
- 绝对化、比较、评价和稀缺表达；
- 商品页与网站基础政策是否明显矛盾。

化妆品、保健品、食品、药品等专项商品不应直接纳入通用快速检查。需要单独规则包和专业复核。

### 7.3 整改复查

适用：用户根据报告完成修改后再次检查。

未来价值：显示“已改善、仍存在、新出现、无法确认”的变化，减少用户逐条人工比较。

复查不应简单等同于免费完整重扫。可以给首次完整检查附带一次限期复查，再对后续复查收取少量额度。

## 8. 收入与成本逻辑

### 8.1 单次检查贡献

每种检查需要分别计算：

```text
单次检查贡献
= 分摊后的检查收入
- 浏览器扫描计算成本
- OCR 成本
- 文件存储与带宽
- 支付手续费
- 可归因的人工支持成本
```

具体价格不能在尚未测出单次成本和节省时间前确定。

### 8.2 固定成本

- Web 应用、数据库和最低运行环境；
- 域名、邮件和监控；
- 规则维护和基准网站回归；
- 客户支持、合同、会计和税务处理；
- 安全更新和故障处理时间。

起步阶段云存储本身可能不是最大成本。例如 Cloudflare R2 当前标准存储包含每月 10GB 免费额度，超出后按使用量计费；但供应商价格、数据处理地区和免费额度都可能变化，正式上线前必须重新核对。

### 8.3 必须持续观察的指标

| 指标 | 用途 |
|---|---|
| 每次完整检查的平均成本 | 判断按次价格是否可持续 |
| 每个客户每月／每年的检查次数 | 判断额度包还是订阅更合适 |
| 完整检查后的复查比例 | 判断复查是否是稳定需求 |
| 新商品检查数量 | 判断是否值得进入 MVP+1 |
| 报告人工解释时间 | 判断产品是否真的减少服务成本 |
| 额度购买后的使用率 | 判断额度大小和有效期是否合理 |
| 续购率 | 判断产品价值是否持续发生 |

## 9. 价格制定原则

本版不确定具体价格，只确定以下原则：

- 价格首先参考用户节省的人工时间和减少的沟通成本，而不是只按云资源成本加价。
- 网站完整检查、新商品快速检查和整改复查应有不同价格。
- 代理套餐必须设置合理额度和超额价格，不提供低价无限使用。
- 额度有效期需要清楚说明，避免用户误解或产生不必要的余额压力。
- 试用价格可以低于正式价格，但必须标注试用条件和期限。
- 白标、团队权限、私有部署和定制规则不应免费附送。

价格、税务处理、退款规则和合同条款在正式销售前应由税理士、行政書士或律师按实际业务确认。

## 10. 最小商业实验

### 10.1 目标

确认目标用户的真实检查频率、偏好收费方式和首次付费意愿，而不是询问“你觉得这个产品好吗”。

### 10.2 样本

先寻找 5 位符合以下条件的代理运营人员：

- 过去一年实际检查过多个日本电商网站；
- 能够回忆网站完整检查、新商品和复查的大致数量；
- 本人参与使用，或能够影响采购决定。

### 10.3 展示材料

- 当前可点击 Demo；
- 一份模拟风险报告；
- 三种检查产品说明；
- 三种不含具体价格的购买方式：按次、额度包、订阅含额度。

### 10.4 需要记录的事实

- 过去 12 个月实际检查的网站、新商品和复查次数；
- 当前一次检查花费的人工时间和参与人数；
- 报告交付给谁，之后还需要解释多久；
- 三种购买方式的排序及原因；
- 如果今天可以使用，愿意先购买哪一种最小方案。

### 10.5 暂定成功信号

- 至少 3 人确认一年内存在多次实际检查，而非只有口头兴趣；
- 至少 2 人愿意使用自己的真实公开网站完成试用；
- 至少 1 人愿意为下一次真实检查付费或支付可退订金；
- 新商品或整改复查在样本中出现稳定重复，而非个别偶发需求。

这些门槛是验证工具，不是最终经营目标。

## 11. 主要商业风险

| 风险 | 可能结果 | 应对原则 |
|---|---|---|
| 使用频率被高估 | 用户不续购，订阅不成立 | 验证期按次，不预设月费 |
| 新商品需求过度分散 | 规则范围迅速膨胀 | 先限定普通商品和固定检查项 |
| 无限次套餐被重度使用 | 收入无法覆盖扫描成本 | 套餐包含额度，超额付费 |
| 报告仍需大量人工解释 | 产品没有真正节省时间 | 记录解释时间，优先改善报告 |
| 客户把结果当法律认证 | 责任和信任风险 | 固定风险提示，不销售“保证通过” |
| 规则更新成本被低估 | 一次性收入无法覆盖维护 | SaaS 或年度更新费承担持续成本 |
| 个人副业变成全天候客服 | 影响主业和生活 | 限制试用人数、服务时间和支持范围 |
| 云端数据引发顾虑 | 客户拒绝上传截图 | 最小保存、自动删除，未来提供私有部署 |
